# KinCall 开发与验收计划

## 1. 产品边界

首个可交付版本面向一台固定 Android 设备、一个已登录微信账号和一个由家属配置的固定联系人。手机已解锁且网络、相机、麦克风和无障碍授权均正常时，老人点击一次家人照片，KinCall 尝试发起微信视频通话。

本项目不承诺绕过锁屏、处理登录验证、后台无人触发拨号、适配任意微信版本或永久免维护。

## 2. 工程原则

1. UI 节点语义优先，控件边界手势次之；禁止未验证的裸坐标链路。
2. 每一步均需满足前置状态和后置状态，否则超时并安全停止。
3. 自动化仅在微信包名作用域内运行，且必须由用户主动发起。
4. 日志不得记录聊天内容、联系人列表、账号凭据或屏幕原始内容。
5. 功能切片通过构建、单元测试、Lint、代码审查后独立提交并推送。
6. 涉及微信交互的切片必须增加目标真机证据，不能用模拟器或日志中的“点击成功”替代最终页面验证。

## 3. 交付阶段

### F01 工程基线与质量门禁

- Gradle Wrapper、最小 Android 应用、严格 Lint、单元测试和 GitHub Actions。
- 验收：`clean testDebugUnitTest lintDebug assembleDebug` 全部通过。

### F02 单联系人老人主界面

- 大尺寸家人照片按钮、明确的空配置状态、防重复点击。
- 联系人显示名和照片仅保存在本机私有目录。
- 验收：状态单元测试、界面可访问性检查、旋转和进程重建测试。

### F03 授权与运行前检查

- 无障碍服务声明、授权引导、微信安装与服务启用状态检测。
- Android 13 及以上侧载“受限设置”说明只做人工引导，不尝试绕过。
- 验收：授权缺失时不得启动自动化；服务作用域仅限微信。

### F04 微信自动化状态机

- 打开微信、搜索联系人、打开聊天、打开菜单、选择视频通话。
- 节点定位器与状态转移分离，支持超时、取消和幂等启动。
- 验收：纯 Kotlin 状态机覆盖正常、超时、未知页面和重复事件。

### F05 安全恢复与语音反馈

- 开始、呼叫中、失败的语音反馈；一次受控恢复；诊断事件编号。
- 验收：异常状态不产生额外盲点操作，日志经过隐私字段审计。

### F06 目标真机验证

- 采集目标微信版本关键页面的 UI 树和截图，建立选择器配置。
- 从微信首页、聊天页和异常页面分别启动验证。
- 验收：至少 50 次测试，固定前置条件下成功率不低于 95%；每次成功均需确认真实呼叫页面，失败均能安全停止。

### F07 交付与运维

- 签名构建说明、安装授权手册、微信升级回归清单和家属故障处理指南。
- 验收：在干净环境完成一次安装和完整操作演练。

## 4. 每个功能的提交门禁

每个功能使用独立提交，提交前必须满足：

1. 工作区只包含当前切片的预期改动。
2. 单元测试和相关设备测试通过。
3. `lintDebug` 和 `assembleDebug` 通过。
4. 审查 `git diff --check`、完整 staged diff 和敏感信息。
5. 提交信息使用 `feat:`, `fix:`, `test:`, `docs:`, `build:` 等 Conventional Commits 前缀。
6. 推送后核对远程分支与本地提交一致。

如果目标设备缺失或微信页面尚未验证，对应功能保持未完成，不以假实现进入提交。
